# 记忆形成、分层、压缩、反思、衰减与遗忘算法

版本：0.3 审核稿。对应 [主方案](../voice-memory-implementation-plan.md)。本页给出本项目推荐算法，不声称是 Tolan 未公开算法。所有阈值为可复现的初始配置，需要通过回放校准，不能当作科学定律或上线成绩。

契约见 [共享模型](contracts/00-common.md) 与 [生命周期模型](contracts/01-lifecycle.md)。接口返回统一 ModuleResult；输入时钟、版本、权限域与 deadline 必须显式传入。所有算法采用同一已授权快照，不使用模型自报的用户 ID 或当前时间。

完整抽取、模型语义消歧、压缩、反思、分层与归档默认后台执行，普通语音回合不串行等待 M01—M10 全部完成。明确控制使用短持久事务与待确认屏障；优先级、资源和质量门槛见 [联合验收规范](engineering-slo.md)。

## M01 候选抽取与记忆准入

输入 AdmissionInput，输出 AdmissionOutput。目标是将最终输入转换为有原话证据的候选，不直接改变持久画像。

1. 校验每条 SourceEvent 归属、revision、is_final 与隐私开关。临时转写、已被修订或已撤销来源跳过；memory_enabled=False 时不生成持久任务。
2. 使用结构化抽取提示，要求每条候选只表达一个可独立更新的事实或事件，并给出原文区间。限制最多 24 条；超限分批，不悄悄截断重要纠正。
3. 标记主语、现实/虚构、肯定/否定、时间、条件、说话来源。服务端按原文验证 quote 与字符区间，不接受模型编造来源。
4. 准入采用硬门槛加规则，而不是“模型给分高就存”：现实域必须是用户自述、确认或合法工具观测；假设、引述他人、玩笑不清晰或错误转写进入 defer/reject。引述他人可形成“用户转述”的事件，不形成未经证实的第三人确定事实。
5. 价值分仅用于通过硬门槛后的保留与排序：显式要求记住为 1.0；明确重要人生事件为 0.8；稳定偏好/互动边界为 0.6；普通日常事件为 0.3；纯寒暄为 0.1。敏感不等于重要，不因敏感而提高主动召回优先级。
6. 多次重复由后续去重归并；每次明确纠正和用户设定的边界不能因为文本很短被过滤。

失败：结构化输出校验失败最多修复一次，仍失败返回 invalid_model_output，原允许留存的输入事件可稍后重试；当前轮使用原话，不能显示“已记住”。

例：“假如我明年搬到北京”不产生 current_city=北京；“别再说我住上海，我昨天搬回北京了”产生更正候选和相对时间表达，进入 M03/M04。

验收：假设、否定、引用、玩笑、ASR 修订各有正反例；不存在无来源 active 记忆。

## M02 实体消歧与规范化

输入 EntityInput，输出 EntityOutput。目标是让“谁、什么、哪里”稳定，而不是用字符串名字作为主键。

1. 候选实体只从当前用户授权域取。用 Unicode 规范化、去首尾空白和已确认别名精确匹配；大小写或拼写归一只适用于允许的语言和实体类型。
2. 将明确的同一性陈述作为强证据：“小林就是我室友林雨”。名字近似、向量相似或共同出现只能产生待确认匹配。
3. 指代使用同一话题中最近、类型匹配且唯一的候选。“他”有两个合理人选时标 ambiguous；不将最高相似度强行当真。
4. 新实体创建候选 ID；合并已有实体必须有可追踪证据或用户确认。合并保留 alias、旧 ID 重定向、时间和审计；拆分错误合并时恢复引用。
5. 人变、称呼变、角色变分开：改名保留 person_id；“前任”和“现任”不合成一个人；同一人角色变化用带有效期的关系记录表示。

复杂度：精确别名查找使用用户域索引；模糊候选最多 20 个。候选分页不完整时不宣布不存在实体。

失败：实体不确定不阻断普通自然回应，但不得据此覆盖唯一事实。验收包括同名朋友、换城市、宠物改名、多人代词和十年后名字变化。

## M03 双时间与时间解析

输入 TemporalInput，输出 TemporalOutput。分别记录：
- 现实有效时间 valid time：信息在生活中何时成立。
- 系统时间 system time：系统何时获知或撤销该版本。
- 事件发生时间与接收时间：用于相对日期和延迟消息。

步骤：

1. 用用户 IANA 时区与 anchor_event.occurred_at 解析“昨天、下周五、去年”。如果 occurred_at 不可靠，使用 received_at 并显式标记 derived，而非伪装精确时间。
2. 明确日期优先，年/月/日粒度分别保存，不将“2018 年夏天”补成某天零点。范围使用左闭右开；精确瞬间使用点事件匹配。
3. “小时候、结婚前”等相对人生阶段建立有证据的关系或阶段范围，不能由用户年龄猜定年份。
4. 纠正发生日期时改变 valid time 并生成新 system 版本；旧 system 版本保留可审计的当时认知，除非用户要求物理删除。
5. 查询必须区分“2020 年你住哪里”和“2020 年时你告诉过我什么”。前者查现实时间；后者还设置 read_system_as_of。默认按当前正确知识回答过去事实。

时间矛盾、不存在日期、时区不明时澄清；未提供结束时间不等于永久有效。生日存月日或完整日期的实际精度，年龄在查询时计算，不每年写入新永久事实。

验收：闰年、跨午夜、夏令时、迟到信息、过去纠错与宽泛日期；不得用记录时间替代事件时间。

## M04 冲突校验与解决

输入 ConflictInput，输出 ConflictOutput；数据库实际修改由 M05 负责。

### 4.1 比较键和谓词注册表

比较键 K = (用户作用域、namespace、subject_id、predicate、规范化条件键)。条件键来自 PredicateRule.compare_qualifier_keys，并排序后规范化。例如“喝咖啡/工作日”与“喝咖啡/周末”不是同一无条件键。

每个 predicate 必须注册：
- single：同一适用条件、相交有效期内至多一个当前值，例如当前居住城市。
- set：可同时多个值，例如喜欢的音乐类型；删除某一值与删除整个集合不同。
- event：事件实例本来可重复，例如多次旅游；必须比较 event_id/时间/参与者，不能因句子相似自动去重。

未知 predicate 先保存非破坏性候选或请求注册，不默认 single。

### 4.2 确定性规则优先

对每个相同键候选，结合有效时间区间进行判断：

| 条件 | 关系 | 动作 |
| --- | --- | --- |
| 值、条件与时间等价 | duplicate/support | 追加独立证据，不新建重复事实。 |
| 条件不同且可同时成立 | conditional_coexist | 共存并保留条件。 |
| 时间不相交 | temporal_change | 保留历史与新阶段，不误报互相矛盾。 |
| single、时间相交、不同值 | contradiction | 进入证据与纠错判断，不直接最新覆盖。 |
| set 中不同成员 | independent | 共存；明确“不再喜欢某项”才失效对应成员。 |
| 明确否定旧事实或转写纠错 | contradiction/retraction | 仅撤销命中对象与区间，不扩大范围。 |

自由文本语义不明确时可使用 NLI/LLM 判断“蕴含、矛盾、不相关、无法判断”，但其结果是辅助证据。模型必须引用双方来源；实体、条件、时区和谓词规则仍由服务端验证。

### 4.3 证据优先级与裁决

用户对自身信息的明确修正优先于旧模型推断；同一来源的新版转写替代旧版；可信工具只在其实际授权和测量范围内可信。不同人说的话、推断与自述不简单比较时间戳。

明确“从上周起搬到北京”可把原城市有效期裁到上周，追加北京阶段。“我从来没住过上海”是撤销错误认知，不应该保留“曾住上海”为生活经历；只保留不含被删除正文的审计关系。

两个同等证据同时指向不同值、缺时间、可疑第三方信息时，标 uncertain 并询问。不得由 LLM 任选一个覆盖。

### 4.4 事务条件与验收

事务中锁定用户事实键或用约束等价实现，校验 expected_refs、privacy_epoch、读水位，发生并发变化则重读重算。single 同一现实区间的“当前分支”不得重叠；历史 system 版本可以保留。

语义推理/NLI、embedding 与证据准备先在锁外完成；事务内只重验版本、来源与确定性约束并提交。多个键按固定顺序锁定，有限次重读仍冲突返回 version_conflict。不得为了完整语义判断持锁等待模型，也不跳过被锁事实后宣称无冲突。

验收包含 A→B→A、过去日期被纠正、同一人两个角色、条件不同、单值并发写与重复事件。模型输出“无冲突”不能绕过数据库唯一性。

## M05 提交、来源胶囊与即时纠错

输入 CommitInput，输出 CommitOutput。目标是让已确认修改原子生效，并在下轮立即可见。

1. 锁外准备有大小上限的胶囊与变更提案；开启短事务，重验 Scope、privacy_epoch、相关版本、源事件存续及确认凭证。不直接执行模型给的任意操作，不在事务里等待模型、embedding、对象存储或重 CPU 任务。
2. 应用 M04 决议，创建不可变 MemoryRevision；追加来源关系。用户级 memory_revision 原子递增。
3. 生成最小证据胶囊：保存获准长期保留的原话片段、原事件 ID/修订号/字符区间、时间、来源类别、摘要哈希及授权版本。胶囊不是完整聊天，不能据此复原已经到期的原始全文。
4. 同事务保存会话增量水位与 outbox。提交后才更新进程内覆盖层并向 UI 确认“已修改”。
5. embedding 未完成的新事实由覆盖层与关键词/事实键可读；不能等向量就绪才认可纠正。
6. 删除、纠正或源修订使关联摘要/反思失效，后台再重建。旧任务重跑检查版本与隐私代次。

如果事务失败，不返回成功；若持久化成功但进程崩溃，恢复从水位重新构建覆盖层，不重复创建事实。明示记忆控制只通过已授权动作进入，语音控制有歧义时请求确认。

语音纠正若未完成语义解释，先持久控制候选并将相关旧字段降为待核验/不可作确定断言，当前会话继续使用用户原话。只有结构化提交成功才说“已更新记忆”。返回 MemoryVisibility 区分 source、overlay、structured、indexed；新会话可读获准来源增量而不必等 embedding。

来源胶囊长期保存需要独立明确的保留授权；若用户不允许，来源原文过期后只能保留允许的结构化内容并降低证据粒度，不能宣称仍能逐字核验。

## M06 分层原理与迁移算法

输入 TieringInput，输出 TieringOutput。分层解决访问速度、成本和长期可追溯性，不负责决定事实真假。

### 6.1 两种层级分开

存储温度：工作上下文（本轮有限输入，不是永久存储）→ hot（近期原子记忆与覆盖层）→ warm（结构化长期记忆和可查询向量）→ cold（带清单的长期事实、证据与摘要）。

抽象粒度：原始记录/证据胶囊 → 原子事实/事件 → 会话摘要 → 月/年摘要 → 人生阶段视图。粒度与温度正交；十年前的重要事实可以是 hot，一个月内的完整转写可以按 TTL 清理。

### 6.2 决策步骤

1. 先排除已删除或未授权对象，pin、活跃未完成事项、最近明确纠正优先 hot。
2. 默认 30 天内已采用的原子记忆 hot；31—365 天 warm；更久进入 cold 迁移候选。这是成本起点，不是“超过一年无用”的判断。
3. 达到 hot 2000 条或在线向量 20000 条软上限时，按“可迁移对象中：保护状态、独立用户确认时间、最近有效使用、价值与迁移成本”排序，选低收益对象先迁移。保护对象超额时告警和扩预算，不悄悄删除。
4. cold 前先写归档，核对校验和、条数、版本及删除代次，切换 manifest 指针后才撤在线大正文/向量。在线保留对象 ID、时间、实体、关键词、摘要路径与归档清单。
5. 冷层命中后以 user pin 或真实有效使用提升为 warm/hot；普通机器预取不计使用。每天提升最多 200 条并使用 7 天驻留冷却，避免频繁冷热抖动。
6. 所有搬迁可恢复、幂等、分批；同一记忆的语义版本与 valid time 不因搬迁改变。

验收：十年未提及的 pin 仍可找回；cold 移动中断不会丢唯一副本；容量限制只影响位置，不冒充遗忘。复杂度是每批 n log n 排序，用户级游标推进，禁止全用户全历史每夜扫描。

## M07 压缩原理与完整实现

输入 CompressionInput，输出 CompressionOutput。这里是有损语义压缩加无损来源索引，绝不是“让模型写短一点”或将 summary 当成新的权威事实。

### 7.1 压缩的对象与目标

原始对话包含重复、寒暄与自我修复；压缩删除冗余表达，保留后续查询和关系延续有用的信息。原子事实、事件、来源胶囊及其版本独立保留或按明确政策处理，摘要只是可重建的导航与上下文加速视图。

目标：在 token 预算 B 内最大化保留的可验证信息价值。对事实项 i，定义价值 v_i、估计 token 成本 c_i、是否选入 x_i。优化目标近似为最大化 Σ(v_i×x_i)，约束 Σ(c_i×x_i)≤B；pin、关键否定、纠正、未完成事项等 mandatory 项要求 x_i=1。

不是在正文上做无依据的字符截断，也不假定固定压缩比永远可达。

### 7.2 详细流水线

1. 选同域、同时间范围、同一输入水位的数据，每批最多 128 个叶记录（硬上限 512）。先过滤删除、已撤销和不适用信息。
2. 构建事实清单：实体、谓词、值、条件、有效期、否定、来源版本。只对完全等价的项确定性去重；同一事件的多个来源保留来源集合。
3. 标记 mandatory：用户 pin/显式要求记住、重大事件、有效纠正、互动禁忌、未完成事项、无法从其他视图恢复的关键关系变更。
4. 计算非 mandatory 价值：用户明确重要性优先，其次未来任务关联、跨会话重复确认与独特性。相同主题的重复语句不靠频次无限放大。以 v_i/c_i 的贪心起点选入，再保证事件、人物和时间覆盖。
5. 若 mandatory 总成本超过 B：拆为多个摘要页或保留原子记录并返回预算不足；禁止丢掉 mandatory 项凑 800 tokens。
6. 给生成模型事实清单与白名单来源，要求返回 SummaryClaim[]，每条引用叶记录和证据，不输出无引用的自由散文。保留“没、曾经、现在、可能”等语义边界。
7. 服务端验证引用存在/同域/同版本；逐项比对实体、数字、日期、条件与否定。用独立验证提示或人审抽样检查语义蕴含，但不能把另一个 LLM 当成证明器。
8. 计算 mandatory coverage = 被正确覆盖的 mandatory 项数 / mandatory 项总数；无 mandatory 时记为 1。通过条件是 coverage=1，且不含无依据 claim、时间错配和类型错误。
9. 如失败，最多一次受约束修复；仍失败返回 accepted=False，保留源与旧有效摘要。输入不够长（默认小于 1600 tokens）则可直接使用已有事实视图，不强制浪费一次摘要调用。
10. 成功写入 SummaryNode、child_refs、leaf_manifest_ref、输入水位、模型/提示/验证版本、token 统计和内容校验和。

原文或胶囊作为 CompressionInput.source_events/evidence_capsules 按授权传入，仅用于本次核验；SummaryClaim 只保存 EvidencePointer，不复制 quote。只有结构化来源元数据可用时，验证范围降为对原子事实保真，不声称已逐字核验原始对话。

### 7.3 多年摘要与防漂移

月摘要可以参考会话摘要，年摘要可以参考月摘要，但每条 claim 必须能沿依赖 DAG 到叶级事实或证据胶囊。抽取关键事实时回读原子记录，不能无校验地“摘要的摘要的摘要”。

人生阶段视图按可验证的搬家、工作、家庭等事件形成时间区间，允许重叠与未知；阶段标签是导航，不推断人生价值。每次生成沿 DAG 验证当前来源是否仍有效，源纠正后依赖后代失效、按需重建。

### 7.4 例子与验收

输入：“以前每天喝咖啡”“最近胃不舒服”“从周一起改喝茶”“只是这阵子，不一定永久戒咖啡”。

错误压缩：“用户不喜欢咖啡”。正确保留：“从已解析的周一开始暂时改喝茶，是否长期持续未知”，并引用原话及时间；胃不舒服属于敏感线索，不自动推断病史。

评估包括 factual precision、mandatory coverage、否定/时间保真、十年随机问答的可恢复性和原文到期后的证据降级。压缩比只作成本指标，不能代替正确性。

## M08 反思与画像沉淀

输入 ReflectionInput，输出 ReflectionOutput。反思从多个经历产生假设；摘要是重述已有信息，两者不能混淆。

1. 以相同主题/互动反馈聚类，默认至少三个不同会话、跨两个不同日期。单次情绪不升级为稳定人格。
2. 去掉同一来源被摘要复制产生的伪多证据；沿叶来源计数，系统自己复述不算新支持。
3. 检索支持与反例，要求模型同时列出“结论、支持、反例、适用条件、何时复核”。不允许诊断疾病、给人贴永久性格标签或把缺失数据当证据。
4. 仅形成 model_hypothesis；影响大的关系与人生判断需要用户确认。默认 30 天或出现反例时复核；不确定性不因为被反复引用而提高。
5. 用户确认后以新确认来源创建事实版本；用户否定则撤销假设并传播失效，不保留在隐形画像继续使用。

画像不无限生成第二套事实库，而是按 predicate/实体选择当前版本的可重建视图。比如“更喜欢先听建议再听解释”可成为有证据的互动偏好；“用户是依赖型人格”不应成为自动沉淀结论。

验收：反例有效、证据独立、十年重复摘要不放大信心；反思不进入角色核心指令。

## M09 时间衰减与强化原理

输入 DecayInput，输出 DecayOutput。衰减只计算“本轮是否值得优先想起”，不降低事实真假、不修改有效期、不删除记录。

### 9.1 公式

对仍合法可用的记忆，使用：

age_days = max(0, now - last_user_confirmed_or_mentioned_at) / 86400

h_eff = h_base × (1 + gain × min(independent_confirmations, cap))

freshness = floor + (1 - floor) × 2^(-age_days / h_eff)

默认 gain=0.25、cap=5。采用半衰期的含义是每过 h_eff，超过 floor 的新鲜部分减半；floor 保留最低可检索优先级。不能将 freshness 解释为“事实为真的概率”。

### 9.2 初始参数

| 内容 | h_base 天 | floor | 说明 |
| --- | --- | --- | --- |
| 瞬时心情 | 1 | 0 | 状态过期另由明确 TTL/规则管理；日后事件回顾仍可查。 |
| 普通日常经历 | 30 | 0.05 | 不主动频繁重复，但可通过相关实体与时间找回。 |
| 稳定偏好 | 365 | 0.20 | 用户一旦明确改变，以新版本处理，而不是等衰减。 |
| 重要人生事件 | 3650 | 0.50 | 作为长期经历保留，并控制主动提及。 |
| 用户 pin | 不采用时间降权 | 1.0 | 仍受隐私、时间与撤销约束。 |
| 未完成事项 | 根据到期与状态单独排序 | 不统一套公式 | 到期只进入待反馈，不推断结果。 |

例：普通经历 h=30、floor=0.05，无强化时 30 天 freshness=0.525，60 天=0.2875；这是排序分，不是删除阈值。

### 9.3 强化、防反馈循环与历史查询

只允许独立用户再次提及/确认或有依据的真实互动增强，按不同来源事件去重；纯检索、系统主动提起、摘要生成和模型自我复述不增加 independent_confirmations。

明确历史查询（如“十年前那次旅行”）应以时间和实体关联为主，freshness 系数降为 0，而不是永远优先近期旅行。未来时间差异常按 0 截断并报警，不产生高于 1 的分数。

验收：十年没提不等于遗忘、用户改偏好立即更新、机器自激循环不产生无限强化、历史问答能命中冷层记录。

## M10 遗忘、失效与保留期

输入 ForgetInput，输出 ForgetOutput。区分六种动作，不能共用一个“记忆权重低就删”的定时任务。

1. 降权：改变检索优先级，内容与证据仍存在。
2. 归档：搬到 cold，语义仍有效；由 M18 确认可恢复。
3. 事实失效：比如旧地址、已取消约定，设有效期/版本状态，历史查询仍可用。
4. 派生视图失效：摘要、反思的来源变更后不再读取；从剩余合法来源重建。
5. 保留期删除：原始转写默认 90 天、拒绝候选 7 天、无支持假设 30 天。用户可配置保留策略；这些默认不适用于已获准长期保留的生活事实。
6. 用户删除：按明确范围撤销原文、事实、来源胶囊、派生、向量、缓存和导出，进入 M19。

### 10.1 具体执行顺序

先检查显式删除与授权撤销，再处理来源到期和派生依赖；再处理事实有效期；最后考虑温度迁移。pin 不抵抗用户删除，也不自动延长原始聊天的保留期。

不因沉默推断偏好变化、不因对话减少自动抹掉关系、不因冷层成本高悄悄删旧记忆。低价值日常数据若未来要自动物理清理，必须作为独立、可见的保留政策经用户同意，不在本版默认启用。

### 10.2 原始资料过期与证据能力

原始转写到期前，只有用户允许时才保留必要证据胶囊。没有允许的胶囊但仍允许保留结构化事实时，标记 evidence_level=summary_only/结构化来源元数据；不得展示无法核验的逐字引用。

原文删除后不承诺逐字重现；当用户选择“忘记这件事”时，不能借口要保留证据而保留该事件的原话。具体清理依赖 M19。

验收：保留期与 pin 独立、旧地址可按历史查但不用于当前建议、删除后归档恢复不会复活、原文到期后的回答标注真实证据粒度。

## 参数、复杂度与算法版本

每次决策记录算法与参数版本；阈值调整通过固定回放比较，不能改变旧事件的事实来源。抽取/压缩/反思使用 bounded batch；冲突按事实键索引；分层和保留期使用队列、水位和游标，不每夜对十年全文调用模型。

accepted 压缩的强制覆盖和事实精确率分别测量；全量质量门槛与 held-out 分组由 [联合规范第 5 节](engineering-slo.md) 固定。不能把 Pydantic 通过当作语义真实、把任务入队当作长期记忆已可读，或为达延迟而静默丢弃难抽取的重要信息。

结构化模型见同目录 contracts；运行期、冷层检索、任务、恢复和十年评估见 [运行与长年维护算法](runtime-and-longevity.md)。
