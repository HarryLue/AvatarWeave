# 召回、语音执行与十年以上维护算法

配套 [主方案](../voice-memory-implementation-plan.md)、[M01—M10](algorithms.md) 与 [契约索引](README.md)。这里的步骤为本项目设计，不是对 Tolan 内部源码的描述。

v0.3 执行约束以 [联合验收规范](engineering-slo.md) 为准：普通路径不等待额外查询/语气模型，资源有界、父 deadline 传播，实时与维护分配不同额度。所有模块输出真实执行与可见性状态，不将异步排队当成已完成。

## M11 查询理解与多查询计划

输入 QueryInput，输出 QueryOutput。

1. 最新最终输入不含搜索对象时，从最近未结束话题和 OpenLoop 取最多两个上下文锚点；有多个合理锚点时标 ambiguous。
2. 抽取已解析实体、谓词、现实时间范围和查询意图：当前事实、历史回顾、继续话题、澄清。现时与历史知识读取分开处理。
3. 第一条使用用户原意的短查询；第二条可加入明确实体或未完成事件；第三条才用于受约束的系统问题扩展。默认最多三个，总预算与 deadline 统一。
4. 普通路径模型扩展默认禁用，使用规则、近期锚点与合法缓存；只有 deep_recall 或经独立验证的增强档允许额外模型调用，受总预算约束。禁止把未确定婚姻、疾病、关系结局等写为肯定语句。生成“用户是否提到过伴侣”仅用于检索，不构成“用户有伴侣”。
5. 稳定且不敏感的必要约束、用户明确纠正、活跃事项通过规则读取，不能完全依赖向量召回。冷层回顾查询附时间窗口与实体，尽量定位到月份/事件而非十年全文。

失败：deadline 到时返回已完成的规则查询；缺少锚点则澄清。验收包含“终于结束了”“还记得那时候吗”“不是上次，是五年前”。

## M12 混合召回、排序与冷层扩展

输入 RetrievalInput，输出 RetrievalOutput。先硬过滤，再评分；不靠评分修复越权、删除或失效。

### 12.1 候选通道

- 事实键/实体精确查询：当前画像、关系与名字别名。
- 关键词：中文采用明确分词/字符 n-gram 配置并版本化，不假定默认英文全文检索适合中文。
- 向量：同一 EmbeddingProfile 与 index_generation 内计算余弦相似度；小规模精确检索。
- 时间：索引用户、valid_time 与事件时间，按明确历史条件找候选。
- 未完成事项：活跃但未完成的约定与结果待反馈事件。
- 冷层导航：用户月/年摘要、实体时间目录与归档清单，不直接把全部旧向量常驻内存。

默认每通道每查询取前 20，合并后最多 60；先按 (object_id,version) 去重。候选被用户/状态过滤后不足时按游标增量补取，不能直接认为没有相关记忆。近似索引上线前必须验证过滤召回率，未达门槛退回分区精确搜索。

这是普通路径起点。query embedding 对同一批查询只请求一次，精确事实/时间/事项/关键词与其独立执行；向量通道等待该 embedding 后再运行。每回合最多四个实际运行分支，各自使用独立 AsyncSession；单会话池只有一个连接时 SQL 短占用顺序执行，不创建无界并发来等待连接。资源准入和池等待计入父预算，不重复为每路支付 query embedding。

可选分支失败可保留合法已完成候选并返回 partial、degraded_routes；取消其他无必要工作。硬授权/删除失败不能降级成普通回答。超时后仍运行的 CPU 工作占有有限槽并跟踪，不能 detached 后当作不存在。每通道重试默认 0，补取也受相同 deadline 限制。

### 12.2 排名融合与重排公式

每个有效通道 r 的名次 k 从 1 开始，通道权重 w_r 初始均为 1：

RRF(i) = Σ_r w_r / (60 + rank_r(i))

R(i) = RRF(i) / (Σ_r w_r / 61)

缺失通道贡献 0，R 限制在 [0,1]。同一查询的重复结果不重复计分。记录实际参与的通道与权重，避免把停用通道误计到分母。

定义 E 为实体关联（明确命中 1、已确认关联 0.5、无关联 0）；T 为时间适配（明确符合 1、未提出时间且无冲突 0.5、不符合则硬剔除）；I 为重要性；F 为 M09 freshness。

普通查询：score = 0.50R + 0.15E + 0.15T + 0.10I + 0.10F。

明确历史查询：score = 0.50R + 0.15E + 0.25T + 0.10I，不因久远降权。

完成硬过滤后，可为当前问题直接相关的用户 pin/互动边界保留最多两个位置，不能强行插入无关 pin。最后做多样性与重复检查：同一事件多版本按问题选择，避免八条结果全是同一话的改写。首期无训练重排器；后续增加模型时需有独立对照。

### 12.3 历史与冷层读取

当前事实只使用当前系统版本、适用现实时间的记录；历史问题可读取 superseded/expired 记录的合法历史区间，不读被撤销或删除内容。“当时知道什么”才按 system time 切片，不能默认把已纠正错误复述成事实。

冷检索分两步：先在在线实体/时间目录与月/年导航中找候选，再读取少量归档片段，解密、校验、过滤当前删除状态后做局部精确检索。一次最多四个片段、8 MiB，超出则异步任务或分页；不让一个含糊问题触发十年全文扫描。

在线 deadline 内冷数据未就绪返回 partial + cold_status=pending。用户可以等待、补充时间/人物；不能回答“你从没说过”。后台结果回传前重新核对当前 generation、话题和隐私版本，过时则只缓存合法结果不主动打断新对话。

读取时返回 MemoryVisibility，目标来源尚未结构化/索引则读取允许的来源增量或返回明确 memory_pending；不能把前缀水位当每条记录都已成为事实。跨会话读取刚保存内容也受该规则约束。

普通输入/记忆预算 6000/1200 tokens、8 条；明确多事件回顾起点 10000/3000、16 条，复杂跨年 16000/5000、24 条，转 deep_recall 并单独限额和最终答案时限。复杂度路由记录依据，不能把慢请求任意重新标记来绕过普通延迟门槛。

验收：冷层与热层同一问题语义一致；稀有实体、旧事实、精确日期、负面约束、删除屏障与不同向量版本均有案例。

## M13 每轮上下文组装与记忆使用决策

输入 ContextInput，输出 ContextOutput。

1. 用固定 persona 与权限边界创建受信任块；将用户信息、检索片段、摘要和当前输入放入明确数据块，不提升指令优先级。
2. 校验选入记忆版本、来源、namespace 和 privacy_epoch，去掉不相干或被撤销记录。restricted 默认只用于用户明确当前请求；不主动开场提起私密经历。
3. 决定 use policy：normal（可回答）、implicit_only（只调整语气/选择）、clarify_only（只可带不确定性询问）、excluded。不把“记得”自动等同于“要说出来”。
4. 普通路径初始 6000 token 输入软预算：记忆最多 1200，摘要约 800；多事件/跨年采用 M12 的明确预算档。必须预留工具与输出空间，先保障规则、最新纠正和当前消息，再按边际信息/成本选择；不得固定八条导致多事件缺证。
5. 工具调用与返回作为完整组，不把一半留在上下文。近期消息以输入水位去重，current_input 恰好一次；若工具/规则已占满预算则返回预算错误，不截断系统规则。
6. 使用真实 tokenizer 或有上界的保守估计；BodyText、ContextBlock 的传输上限与模型 token 预算分别检查。生成 ContextManifest，包含选入/排除原因、来源版本、水位和裁剪信息。
7. 生成前及每次发布新语音片段前验证 owner/generation/privacy fence；旧 generation 不复用先前提示缓存来回答新问题。

执行检索、组装与模型调用时不持有事实锁。每个语义输出片段检查有效授权；不为每个约 20ms 媒体帧做独立 SQL 查询。片段级检查/活动会话失效通知仍必须满足删除屏障，单靠固定 TTL 缓存不构成授权保证。CPU 解析和 token 估算超出小规模上限时移到受限执行资源，不阻塞音频事件循环。

普通检索相关不足时宁可少用记忆；不能把整份人生摘要每轮塞进去，也不能让摘要永久遮蔽原子事实。

验收：话题突变、十年前回顾、隐私回避、最新纠正、工具组完整、重复消息、长输入与 token 超限。

## M14 人格、情感与表达适配

输入 PersonaInput，输出 PersonaOutput。

加载人工批准角色版本，核心身份与能力边界不由记忆修改。根据最近少量用户明确文本、当前话题与互动偏好生成 ToneState，初期标签为 neutral/playful/calm/concerned/focused/unknown。

普通回合先使用规则/仍有效的 ToneState，不每轮等待额外情感模型。较复杂语气推断可后台更新带版本状态，下轮使用前验证话题与过期；不能让后台旧情绪覆盖用户当前明确要求。

语气使用迟滞与过期：需要明确新线索或两个连续弱线索才转换；默认五分钟/话题改变后复核，低置信退回 neutral，不在用户一句玩笑后剧烈变脸。用户明确“别安慰我，给建议”优先于自动语气推断。

人格漂移检测检查行为边界、身份自洽与用户明确表达方式；不是用固定措辞控制全部回答。表达通过措辞、语速、停顿、音量和资源白名单动作联动；provider 不支持参数则不发送伪参数。

关系随真实共同经历发展，使用可撤销的关系摘要与互动偏好；不默认维护“亲密度分数”来驱动依赖或付费。角色虚构经历放 character_lore，不混入真实共同经历。

验收：用户悲伤时角色变温和但不改身份；十年迁移后仍保留批准角色版本与重要互动边界；情绪标签不永久成为用户人格。

## M15 未完成事项、人生事件与主动关怀

输入 OpenLoopInput，输出 OpenLoopOutput。

从明确计划、约定、目标抽取事件与时区；若“下次”无具体时间则保存不确定区间，不编提醒时间。事件经历 planned→pending_outcome（已过时间但结果未知）→completed/cancelled，延期建立新版本。

主动追问评分只用于已授权的会话内候选：问题相关度、到期距离、重要性和用户主动跟进选择。每轮最多一个，默认同一事项 72 小时冷却。用户说“不想再谈”立即关闭跟进并创建互动边界。

人生阶段通过已确认的搬家、工作、家庭变化等事件组织导航；不同阶段可重叠。死亡、分手、健康经历等默认不自动周年提醒，用户明确选择后才纳入纪念回顾。不要通过推断“该到了”自动编造结果。

本模块不发送推送、不创建系统闹钟；未来通知需独立调度、授权、送达和撤销契约。验收包括日期过去、用户未回来、长期未完成、明确拒绝追问与人生事件时间纠正。

## M16 语音、动作与实际执行记忆

输入 OutputInput，输出 OutputOutput。

1. 回答、语音与动作绑定同一 turn_id/generation_id/owner_epoch；模型动作建议经资源白名单与客户端能力校验。
2. OutputPlan 只是计划。分别记录 generated、published、started、partial、completed、interrupted/cancelled/failed/unknown。
3. v1 客户端保留现有行为，不能宣称支持回执；v2 使用明确 topic 与 schema，接收方校验发布者、会话、代次、序号和过期时间，按 command_id 去重。
4. 用户打断先停止旧音频和相关动作，再撤旧 generation；重新获取最终输入与上下文。迟到回执可写诊断，不把 cancelled 改回可执行。
5. 精确字词进度仅在 provider/SDK 提供可验证的媒体时间与文本对齐时使用。否则按语段/输出粒度记录，safe_spoken_prefix=None，不用时长比例猜字。
6. 共同经历只写“有证据发生的事”：用户说过某事可存自述，模型计划送祝福未播放不能存“已经祝福”。设备播放完成也不能存“用户已听懂”。
7. 误打断恢复只恢复仍有效、未受纠正/删除影响的输出。重连新 Worker 读取账本，不重播旧欢迎语或已取消动作。

取消传播到流式模型/TTS、客户端动作和资源 lease；不可即时停止的本地推理占有限 detached 槽并丢弃旧结果，实际结束后才释放。若使用 Kokoro，推理锁的排队和单实例能力单独纳入真实语音并发验收，不能简单删除锁破坏共享模型安全。

播放与网络无法原子撤回已送出字节。删除接口要区分逻辑撤销时刻、取消传播和设备最后观测；不得承诺用户点删除的一瞬间所有在途音频消失。

## M17 持久任务与作业调度

输入 JobInput，输出 JobOutput。

事件/记忆提交与 outbox 同一事务；dispatcher 将 outbox 去重转为 Job。claim 使用行锁与跳过已锁定记录的等价机制，生成租约令牌；后续 renew/complete/fail 必须持有租约及正确 attempt。

至少一次执行，输出以业务幂等键唯一。进程崩溃后租约到期可重领；任务重领时首先核对来源、隐私版本与输入水位。任务被新版本替代则 obsolete，不再用旧结果写回。

失败退避：delay=min(30×2^(attempt-1),3600) 秒，并加受控 0—20% jitter；默认最多五次。schema 永久错误、无权限、来源已删不按网络故障无限重试。死信有最老年龄告警和人工重放入口。

调度采用增量水位、dirty memory refs、受影响依赖队列；日/周/月归并只处理新变化。任务必须有每用户预算和全局并发上限，禁止十年每轮重扫。

队列按 control/dialogue/deep_recall/maintenance 分配保留额度，后台任务按用户公平轮转、限制单用户运行数；认领用短事务，执行网络/CPU 工作时不持认领锁。SKIP LOCKED 只用于队列，不用于事实读取“跳过冲突然后当作完整”。

ready queue、outbox 和 payload 存储共同约束总条数、字节与最老年龄；达到上限先合并重复维护、推迟可选任务，仍满则拒绝新的非必要保存承诺。不能把积压从队列搬到无界 outbox 表逃避限额，不能丢弃已经确认保存的来源。控制操作有保留但仍有界。

分别推进 source/structured/index 连续 settled 水位，记录每目标事件状态及 queue wait。普通结构化 P95≤5s、向量 P95≤10s 的建议门槛包含排队；超时、失败、待确认均有状态和告警，不通过重命名分类隐藏积压。详细连接池、配额和压力口径见 [联合规范](engineering-slo.md)。

验收：进程中止、重复完成、租约过期、旧结果提交、任务积压、删除中重试。

## M18 冷存储、归档与恢复读取

输入 ArchiveInput，输出 ArchiveOutput。

### 存储格式

PostgreSQL 存权威目录、当前事实索引、来源依赖、权限、删除屏障与摘要导航；大批 cold 原子记录和证据胶囊存加密版本化对象。对象按用户及时间片分片，清单含 schema、记录数、SHA-256、key_version、水位与隐私代次。

对象内容采用可迁移的规范 JSON Lines 或等价公开格式，压缩使用标准算法，压缩后再做经审查的信封加密。不能自行发明密码协议；运行时通过 KeyProvider 取密钥，不在文档或数据库字段保存明文根密钥。KeyProvider 的具体托管服务在部署评审锁定。

### 两阶段归档

write：读取固定版本叶记录→生成内容清单→压缩加密→写 staged 对象。

verify：回读解密→校验 checksum、条数、scope、版本与删除状态→事务切 active 清单。

只有 verify 完成才允许移除在线大正文/向量；保留目录与指针。写对象成功但数据库未切换可重试或回收孤儿对象，不能丢源。

### 冷层读取与恢复

每次通过在线目录定位 manifest，再从对象读取指定片段；即使对象很旧，也必须检查当前 privacy_epoch 和逐记录 tombstone。不能只相信归档时的合法状态。高频命中可提升温度，受 M06 配额限制。

归档校验失败返回 storage_unavailable/evidence_missing 并尝试受控副本恢复，不能让 LLM 补缺失内容。定期抽样回读，季度演练恢复到隔离环境；记录对象、密钥与目录均可用才叫可恢复。

KeyProvider 由运维平台提供能力接口，业务模块的归档输入仅传 key_version，不传明文密钥。密钥轮换与账号删除按 M19/M20 管理；加密不能代替授权和删除。

## M19 隐私、删除传播与防复活

输入 PrivacyInput，输出 PrivacyOutput。

删除控制必须明确目标：单条事实、源事件、时间范围或账号。单条独立事实删除与“忘掉这次经历及其派生”不同，确认 UI 展示范围，不能对空目标猜成删全部。

1. 认证并验证目标及确认事件，在事务中撤销目标可见性、提升 privacy_epoch、创建 tombstone 与 DeletionJob。
2. 活动会话、上下文快照和准备发布的输出重新验证 epoch；不再提交旧来源生成的后续片段。已经送出内容不可逆，记录取消观察与边界。
3. 对来源依赖 DAG 反向遍历：目标事实、摘要、画像、反思、embedding、缓存和导出失效。混合摘要先整体下线，再从剩余合法来源重建。
4. cold 对象立即在读取路径屏蔽相关记录，再异步重写不含删除内容的新对象并切指针；旧对象与副本按删除 SLA 清理。不能只删除在线向量而保留一个可下载的旧全量包。
5. 后台任务、索引迁移、备份恢复和导入提交前检查 tombstone/epoch。源被删除即停止引用，不能从旧摘要再抽取回来。
6. 删除任务记录各存储类别进度及备份失效时间；完成表示约定范围内的物理清理，不把“202 Accepted”显示为全部清理完成。

tombstone 只保留必要 opaque ID/水位，不保留被删正文或可被字典攻击还原的低熵文本哈希作为“匿名备份”。备份不能立刻逐行清理时，明确有限保留与恢复后先重放删除状态。

不记忆模式不持久正文、摘要、向量、来源胶囊、异步正文载荷或完整提示；只留最小技术计数。原始音频默认不保留。第三方模型处理边界必须单独说明。

验收：删除同时压缩/反思/导出/索引、冷对象重写中断、从旧备份恢复、历史查询、账号恢复均不复活。

## M20 十年演进：schema、模型、密钥与索引迁移

输入 MigrationInput，输出 MigrationOutput。

先建立 versioned reader/writer 和迁移清单；切换前只写入新空间，保留可回滚读路径，不在线原地破坏旧数据。每批使用游标、预期源版本和当前删除水位，过时数据重读。

- schema：添加字段/版本并提供显式转换；未知语义失败，不静默猜测。验证时间、namespace、证据关系未变化。
- embedding：新模型/预处理/维度创建新 profile 和 index_generation；从合法结构化内容重算，查询双跑对比后切读；不得把新旧向量放同一空间比较。
- 密钥：使用新 key_version 重加密并回读验证后切 manifest，旧密钥在所有合法对象迁移和备份策略完成前不能销毁。
- 归档格式：旧 reader 与新 writer 协作，解密校验原对象，转换后校验记录语义与来源集合，不只比较字节数量。
- 备份恢复：隔离恢复目录与对象，先应用最新删除/权限账本，再完整性检查与查询回放；未完成删除重放时禁止对外读取。

验收门槛：checksum failure=0、deleted_records_reintroduced=0、scope/valid-time/事实数量变更均有解释、基准集不退化。切换需要审核，dry_run 不改变活动指针。线上停机窗口与预算由部署计划确定，不在开发中擅自切生产。

## M21 十年评估与失败归因

输入 EvaluationInput，输出 EvaluationOutput。使用可注入时钟和带真实预期的事件时间线，不靠让模型生成十年聊天再自评来“验证十年”。

数据集分三层：
1. 确定性构造：十年时钟、实体变化、A→B→A、跨日期、冲突、删除、断线和迁移；ground truth 直接来自事件图。
2. 经授权且脱敏的真实使用样本：保留真实话题跳转和语音错误；与合成样本分别报告。
3. 外部基准：LongMemEval 的长期问答能力与 LoCoMo 的跨会话场景，遵守数据许可；不把其规模说成十年生产验证。

测试分别固定基础模型、token 预算与声音，比较近期窗口、普通 RAG、双时间/混合召回、完整系统；移除分层/压缩/关系/输出账本做消融。

指标：有效记忆召回、无依据结论率、时间更新正确率、拒答/澄清正确率、mandatory coverage、冷层恢复成功率、跨用户泄露、删除复活、每用户各年成本、P50/P95 端到端语音延迟。语气与陪伴自然度使用盲评、人审与用户反馈，不把返回频率当成关系健康。

失败归因按抽取→实体→时间→冲突→提交→索引→检索→上下文→生成→媒体执行定位，保存版本引用而不是复制所有私人正文。长年能力以回放、故障演练及真实长期观察逐步证实，不承诺已验证十年留存或“已经超越 Tolan”。

## M22 身份、会话与十年关系归属

输入 IdentityInput/SessionInput，输出 IdentityOutput/SessionOutput。

长年正式记忆必须绑定可恢复账号。采用经审查的 OIDC Authorization Code + PKCE 认证库，验证 issuer、audience、state、nonce、签名、期限；外部主体映射到内部 user_id，外部邮箱改名不改变内部 ID。

匿名只做临时体验，不允许把一个 cookie 当十年唯一身份。升级时同时证明持有匿名会话和已认证账号，生成一次性迁移操作，列出待转入内容，幂等完成。账号恢复、更换认证提供方、用户导出导入有独立审核路径，不按昵称/名字自动找回。

服务端生成 session_ref、room、participant identity 与 companion 授权，dispatch 只传引用；Worker 读取数据库验证实际房间和绑定，不能信任客户端 metadata。共享 API key 不等于用户身份，公开 demo Token API 不能进入私人记忆房间。

每个会话用租约和 owner_epoch 防双 Worker，创建/恢复/结束幂等。账号转移、家庭共享不自动授权读取私人对话。关系记忆跟随用户和 companion，不跟随某台设备、房间名或渲染资源文件。

## M23 输入记录、模型网关与生成栅栏

输入 InputEventInput/ModelTaskInput，输出 InputEventOutput/ModelTaskOutput。

输入桥先验证最终转写、用户归属、修订号和 generation；临时 ASR 可以用于 UI 但不能进入持久画像。用户纠正字幕后保留来源修订，并撤销依赖旧转写的候选和后续输出。

模型网关按 task 选择明确的 profile/prompt/schema，约束最大输入输出、deadline、重试和消费预算。结构化响应必须经 Pydantic、来源检查和算法规则后才进入下一模块；不相信模型自报完成了权限检查。普通对话使用流式输出适配，最终 DialogueDraft 是账本对象，不能为了凑完整响应阻塞全部 TTS。

预生成第一版关闭。后续可在输入预测阶段做可撤销工作，但最终提交必须与 final revision、memory revision、privacy epoch、owner epoch 一致；旧候选不能产生不可逆工具效果。主动开场、文字消息和语音都走同一上下文与栅栏。

失败时明确不能保存/没有足够证据，不谎称记住或听清。首期保持现有 provider 分层，业务记忆不写进受来源清单保护的厂商插件。

## M24 embedding 与检索索引

输入 EmbeddingInput，输出 EmbeddingOutput。

文本渲染模板固定版本，包含主体/谓词/值/条件及必要时间，不把完整十年摘要拼进每条向量。相同 (record version, model profile, render version) 去重，同一模型空间复用。

每条向量检查维度、有限数值、非零范数；按 profile 决定归一化，query/index 完全一致。数据库写入 record 仍合法且隐私代次匹配时才提交索引指针；旧索引版本不参与当前查询。

首期 warm/hot 上限内精确检索，按用户/作用域分区；是否采用近似索引由真实过滤召回与延迟决定。选型时核对 pgvector 当前数据类型/索引维度限制，不把示例维度当任何模型都能用。

在线 query embedding 与后台 index embedding 使用不同保留额度，并受同一供应商账号总 RPM/TPM/inflight 约束。普通 query 单次合批、deadline 不重试放大；后台失败有限退避。索引完成后更新目标事件状态和连续水位，未完成的结构化新事实仍由覆盖层/精确读取提供，不等待向量才算可见。

大规模重建按游标与配额，优先活跃用户和 pin/关键事实；cold 只保留导航或延迟索引，避免十年全量向量常驻高成本在线库。

## M25 导出、导入与可携带性

输入 ExportInput，输出 ExportOutput。

导出包含开放 schema 的事实/事件、版本、时间、来源胶囊权限、摘要 DAG、角色 ID/版本及文件清单，不只给无法解释的向量。原始对话仅在仍存在且用户明确要求时包含。

包使用完整性校验与受控加密/短期下载；不导出内部密钥、其他用户数据或服务凭据。下载链接不进入长期记忆。导出后发生删除时撤销仍可访问的服务器副本；用户已下载到其设备的副本无法由服务器保证远程销毁，应说明边界。

导入先 dry-run，重映射内部 ID、检查所有者证明、schema、引用、时间、冲突和 tombstone；导入内容不因“来自本产品旧文件”就自动成为更高权威。用户已删除记录不能被旧包静默复活，需明确恢复选择并有新的授权事件；默认拒绝重引入。

十年可携带性不等于承诺公司永久运营；应让数据格式、来源与用户控制不依赖单一模型供应商。

## M26 repository、目录与并发读取

输入 RepositoryInput，输出 RepositoryOutput。

repository 统一作用域、权限、有效性、privacy 栅栏与游标。read_versions 逐版本精确读，scan_fact_key 用事实键索引，scan_period 用用户与时间索引，read_sources 支持来源胶囊粒度。所有读返回 read_watermark，不偷偷跨快照混用。

事务写由 M05/M19 统一提交，其他模块不得绕 repository 直接按模型提供的 ID 拼 SQL。分页结束前不能宣布集合完整；并发改变导致读水位失效时重新读取或显式 partial，不在内存侧拼成一个伪原子快照。

缓存键包含 scope、memory_revision、privacy_epoch、算法/模型版本，负结果缓存同样受版本控制。缓存 TTL 不能替代删除栅栏；只缓存已授权数据，分享和输出前再次核对。

每个并发任务使用独立 AsyncSession，事务限时且不跨网络模型调用。按全进程连接预算限制池与 overflow；控制/在线/后台的池隔离不免除总连接和数据库 I/O 压力。对刚提交目标事件提供来源/处理状态查询，不要求等待所有旧任务完成才能确认本条事件的状态。

验收：读写并发、热冷目录切换、分页中删除、不同角色同名实体与负缓存失效。
